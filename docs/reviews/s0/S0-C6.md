## Owner decisions after review

1. **Unhandled exceptions (TD-9):** add a catch-all handler: 500 `internal_error` in the
   standard body, the exception logged with its traceback, nothing about it sent to the
   client. Built in S0-C7 (TD-9's target); recorded in TD-9.
2. **Unreadable `StaleDataError`:** stays 409 (conservative). The non-versioned racing-delete
   API test uses SQLAlchemy's real wording, so a wording change fails it.
3. **Versioned row deleted mid-request:** check whether it still exists and answer 404 if not.
   **Built in this checkpoint:** a `before_flush` hook records the versioned rows each flush
   writes (a failed flush clears the session's dirty list); on a stale error `get_session`
   rolls back, looks them up, and raises `NotFoundError` if any is gone.
4. **Soft-deleted meanwhile (asked after pass 3):** also 404, precisely: a row is gone if it no
   longer exists, or is soft-deleted now but wasn't when this request loaded it, so a version
   race while restoring a soft-deleted row stays 409. Recorded in design-doc §3 and the build
   plan.
