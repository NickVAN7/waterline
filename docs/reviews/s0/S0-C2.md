## Owner answers to the review questions

1. **Health response shape:** when the database is unavailable, the 503 switches to the
   standard `{code, message, details}` error format once S0-C6 adds it. Recorded in the build
   plan's "API foundations" section and Checkpoint 6's scope.
2. **Factory seeding wording:** the owner asked why the code reseeds before every test and
   whether a test run alone gets the same data. Demonstrated with a throwaway test: with
   per-test reseeding, a test got identical data after other tests and alone; with a single
   session seed, its data changed with what ran before it. `testing-strategy.md` now describes
   the per-test reseed exactly. The demo also showed that factories produce random strings
   rather than realistic fake values: logged as **TD-5** (Slice 1).
3. **SQLAlchemy version:** the build plan and `backend/CLAUDE.md` now say "SQLAlchemy 2.x
   (2.0-style typed ORM)". `Enum(create_constraint=...)` still defaults to false in 2.1, so the
   build plan's note about it stands.

## Owner decisions during review

- Health 503 moves to the standard error format in S0-C6.
- SQLAlchemy is specified as 2.x in the build plan.
- testing-strategy.md's seeding wording matches the code (reseeded before every test).
- Realistic factory values logged as TD-5 for Slice 1.
