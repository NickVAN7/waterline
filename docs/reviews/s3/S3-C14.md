## Decisions during the checkpoint

- **DL-418** (owner, Nov 25, 2026, at the start, both as recommended): cells read as on screen
  (labels, names, display IDs, ISO dates, empty for nothing); the proposed `columns=` sets; UTF-8
  with a BOM; `Waterline-Truncated: true` when the cap cuts an export short.
- **No spec tests:** no action or rule changed; the exports use the lists' own actions
  (`task.view`, `requirement.view`) and loaders, so their scoping and the export-control gate.
- **Shared pieces** (their first consumers): `app/core/csv.py` (`cell()`, the formula escaping,
  with the line naming what it defends against; `CsvExport`; `export_query()`, the list's query
  model plus `columns=`; `csv_response()`), and `app/core/labels.py` (the labels; a test checks
  every enum member has one).
- **The exports call the lists' own queries** (`fetch_ranked` with `TASKS` and `TREE`, the same
  caps), so filters, the task list's sort, scoping, and the cap are the list's; the requirement
  export leaves the context ancestors out (DL-351). The routes sit before `…/{number}`, which
  would read `export.csv` as a number.
- **The tasks column** is empty for a requirement with no tasks, and "1 of 2 done" otherwise.
