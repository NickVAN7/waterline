## Decisions during the checkpoint

- **Subtask limits** (owner, Nov 24, 2026, before building; DL-412): title 200, description
  2,000, in the schema doc.
- **The subtask service is its own module, layer 4b** (`app/services/subtask.py`, above the
  task service it reads tasks through, as `requirement_approvals` above `requirement`); the build
  plan's layer table and the import contract list it. Its queries live in `TaskRepository`, as
  the task area owns `subtask` (the feature map).
- **The counter:** `NumberingService.allocate_subtask_number`, a `direct_update` of
  `task.next_subtask_number + 1` (the developer guide's counter pattern): no `version` bump, the
  task's `updated_at` moves.
- **Moves within a task** run one at a time on the task's row (`FOR NO KEY UPDATE`, the lock
  the counter's UPDATE takes), with `anchor_position()` (given `within="this task"`) and
  `write_ranks()`.
- **No single-subtask read**: the row lists none; PATCH and the move return the item.
