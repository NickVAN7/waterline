## Owner feedback after the report (fix commit)

- **The approvers' list opened by itself when the dialog opened** (owner, Nov 27, 2026). Cause:
  PrimeVue's AutoComplete opens its list when a search answers, and two frames after one starts,
  wherever focus is; a dialog's first focus can pass through the picker's field (the browser's
  own `showModal()` focus, before `ModalDialog` moves it to `data-autofocus`), which starts the
  search. Headless Chromium focuses the approvers group first, so neither the specs nor the
  e2e run showed it. Fixed once, in `PersonPicker`: an opening list closes unless its own field
  has focus (`before-show`), so every dialog with a picker is covered. Tests: `keeps its list
  closed when focus has moved on before the search answers` (failed before the fix); the spec
  helpers now focus the field before typing, as a user does; `e2e/approvals.spec.ts` checks the
  list is closed once the dialog has opened. Sibling: `AddMemberDialog` starts on its title for
  the same reason (S3-C0l), kept.
- CI's lint warning (`describedBy` shadowed in `PersonPicker`'s slot) renamed.
