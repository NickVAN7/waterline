## Questions still open for the owner

1. **Password length at sign-in.** `SignInRequest.password` has no length limit, so a very long
   password costs an Argon2 verification (small extra cost: Argon2 pre-hashes the input; sign-in
   throttling is already deferred to before the first non-local deployment). Reject passwords
   over the policy's 256 characters before verifying, or a looser cap (e.g. 1024)?
2. **The old session at sign-in.** Sign-in always creates a new session, and leaves alive any
   session the browser already sent (design-doc §4 only says never reuse one; the server mints
   every token, so this isn't session fixation). Delete the old one at sign-in?
3. **403 and 415 in the OpenAPI schema.** The middleware returns `origin_rejected` and
   `unsupported_media_type` before routing, so no route declares them. Declare them on every
   mutating route for the generated client (S1-C14's error handling), or is the shared
   `ErrorBody` enough?
