**Its questions, and what happened to each:**
- The strict-coverage gate's own test ran only `tests/unit/rules`, so it failed once `app/authz/`
  had code: updated by the implementing session (not a spec test) to run the authz unit tests too.
- A workspace member creating a project in an org they have no role in: 403 or 404? §4
  Visibility says staff see only the orgs they're assigned to, so the implementation returns 404
  (`can_see` is false for the org); the unit tests assert only that `authorize` is False.

  the docs; `allowed_actions` lists only actions at the target's own level.

  `tests/api/test_deps.py` (sabotage-checked with the dependency cache off).
