## Open questions for the owner

1. **Maximum rank length (TD-69).** Drops into one gap lengthen a rank about one character every
   six moves, and past about 2,700 bytes Postgres refuses the btree entry on `task`'s rank
   index. Options: (a) a cap (e.g. 255 characters) where a drop that would exceed it rewrites
   the ranks of that gap's siblings in one transaction; (b) a cap that refuses the drop with a
   422; (c) no cap in v1, accepting the failure mode. Recommendation: (a), decided before S2-C7.
2. **Pinning the collation.** Rank order matches Python's only under `en_US.utf8`. Options:
   (a) an integration test in S2-C7 that sorts generated ranks with `ORDER BY` and compares
   them with Python's order; (b) `COLLATE "C"` on every rank column (a migration and a
   schema-doc change). Recommendation: (a): cheap, and it fails loudly if the collation ever
   changes.
