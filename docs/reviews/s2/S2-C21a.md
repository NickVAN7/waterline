## Open for the owner

1. **Archived projects** (security-reviewer, checkpoint-reviewer): `project_member.manage` is a
   change, so an archived project refuses it, and no one, its admins included, can list its
   deactivated members (no checkbox; a 422 on the parameter). DL-294 reads that way to the
   letter. Options: (a) keep it (recommended: the members list is read-only on an archived
   project, and reactivating is done from the workspace's lists); (b) decide on the live project,
   as Trash does (DL-220).
2. **The admins' hint on a list with nobody at all** (checkpoint-reviewer, ui-reviewer): "No
   members yet. Deactivated people aren't listed. Select Show deactivated to see them." also
   shows when nobody is hidden (a project with no explicit members). Options: (a) keep it;
   (b) reword it so it doesn't say anyone is hidden: "Deactivated people aren't listed here. To
   include them, select Show deactivated." (recommended: one string, no extra request).
